# 展厅视觉升级：影响、维护与回退

记录日期：2026-11-17。本文依据当前 `src/models.js`、`src/scene.js`、`src/exhibit.js`、`src/main.js`、`src/simulation.js`、`style.css`、页面模板与单文件构建脚本核对实现，并收录主任务提供的本轮浏览器回归结果。源码核对与实际回归分别记录；未列为已通过的检查项不据此推定通过。

本轮视觉目标是提高设备结构辨识度、空间层次和客户导览效率。原图对象、位置、区域数量及模拟计算保持各自的数据来源；布景和视觉细节不能反向变成现场事实。

## 直接、二阶与三阶影响

| 改动 | 直接影响 | 二阶影响 | 三阶影响 | 抑制方案及当前实现依据 |
| --- | --- | --- | --- | --- |
| 倒角、螺钉、导轨、管线和内部机构细化 | 几何量、材质表现和设备轮廓增加；同屏可拾取表面更多。 | draw calls、阴影绘制、raycast 候选与部件选中边线的生成成本可能增加；装饰件若归错父级，拆解时会留在原地或跟错部件。 | 移动端操作延迟；观众点到装饰面后看到错误说明；反复进入结构累积资源会降低长时间展示稳定性。 | `detail` 区分近景，细螺钉仅在详情创建；复用几何，并按父级与材质实例化重复件。新增可见网格必须归属正确 `partId` / `entityId`，不能放在可拆解部件之外。拾取继续限制在当前可见设备/部件。模型越精细，越应检查“点击表面 → 名称 → 单件拆出 → 隐藏”是否是同一对象。 |
| 共享材质、几何与 `InstancedMesh` | 减少重复资源，重复细节可合批绘制。 | 修改共享颜色会串改其他设备；跨活动父级合批会破坏门、夹具和滑台动画；选中整批实例时无法自然区分每颗螺钉。 | 单件动作失真，或资源回收误伤仍在显示的设备；切换次数增多后出现 GPU 内存增长。 | 当前 `repeat()` 以父级、几何和材质分批，保留铰链/运动组；实例作为所属总成的细节，不新增独立维修部件语义。`ownMaterial()` 为单机状态灯克隆材质；选中材质克隆后恢复原材质；模型 `dispose()` 释放实例缓冲、专属管线几何及专属材质，不释放模块共享池。车间 `disposeTree()` 已补充 `InstancedMesh.dispose()`，覆盖警示条和展示框架的实例缓冲；模型与车间资源按各自拥有者释放。 |
| 环境反射、主补光、阴影与接触暗部 | 白色喷涂、金属、玻璃和深腔体更易区分，设备更有落地感。 | 2048 阴影图比 1024 有 4 倍纹素；透明表面增加叠加绘制，灯光和阴影会竞争手机 GPU 预算。 | 全线运行或高 DPR 设备上可能降帧、发热；更深阴影也可能遮住机构和标注。 | 当前 DPR 上限 1.5；窄屏初始化使用 1024 阴影图、其他使用 2048；只有主方向光投射阴影，补光不再增加阴影图。玻璃采用透明材质且不启用 transmission，透明件不投射阴影；接触暗部为小型程序化纹理。若预算不足，先降低阴影图/DPR和非关键小件投影，再删模型细节。宽度阈值只是默认值，不能当作设备性能检测；横竖屏切换和实际手机表现仍需验收。 |
| 固定视点与“专注展示” | 用户能快速查看总览、反向、工艺近景与俯视；隐藏侧栏后画面更大。 | 镜头、按钮激活态、当前选择、详情面板与画布宽高比必须一致。返回方式和恢复面板入口需要明确。 | 状态若失配会导致方向丢失、镜头与说明对象不一致，或巡览夺回用户镜头。 | 已实现：工艺近景优先聚焦 `selected`；无有效选择时主界面同步选中首个非辅助对象（有独立设备时优先首台设备）。`currentCamera/markCamera()` 同步按钮，手动接管取消过渡、停止巡览并清除固定视点激活态；focus 模式 resize 保留水平构图。进入设备结构恢复侧栏，Escape 可退出专注展示。返回结构外保留 selected 并重绘详情，镜头回总览，仍不宣称“恢复上一镜头”。进入详情恢复面板已通过本轮回归；其他已实现状态联动继续列入完整复验。 |
| 减少常驻标签，增加详情引线 | 全景更清爽，部件名称与指向更分离。 | 隐藏的名称降低首次发现概率；标签碰撞规则会让部分部件暂时没有标签；引线可能穿过模型或相互交叉。 | 用户可能误以为未标注对象不可点，或者把引线当作物理连线；错误指向会损害部件说明的可信度。 | 当前全景非选中标签上限为窄屏 3、其他 7；选中项优先，另有二维图、清单、搜索和部件列表入口。详情标签优先使用 `labelAnchor`，否则取部件世界包围盒中心；引线不接收指针事件。当前布局检查屏幕边界和矩形碰撞，不等于三维遮挡检测。需检查装配、半拆解、全拆解及旋转后引线端点；隐藏部件要同步去除标签，低对比装饰件不能遮挡真正可操作入口。 |
| 展示框架、灯带、背景与地面 | 场景有统一的展示空间，缺少照片时仍能形成完整构图。 | 布景会改变遮挡、反射、空间尺度印象，也增加资源。 | 观众可能把展示框架误认作真实洁净室、实体墙、设备间距或合规安全边界。 | `exhibit.js` 已按四种材质合为 4 个静态实例批次，减少框架绘制批次；仍明确为 presentation scenery，不写回 `source-layout.json`，不加入原图设备/区域统计、拾取实体或物流碰撞边界。框架保持观众侧开放；页面保留“按图定位 · 布景与设备为示意”，详情保留通用结构说明。检查移动端隐藏局部提示后，布局依据与详情仍能说明事实边界。不增加未经提供的米制尺寸、洁净等级或设备性能。 |
| 更复杂的视觉更新与离线打包 | 单帧需要处理更多模型、标注和相机状态；新辅助模块进入构建产物。 | 若把动作绑到实际帧数、DOM 定时器或网络资源，会影响暂停连续性和断网加载；仅修源码而未构建会让交付页停留在旧版。 | 长时间演示的计数、动作与说明不同步；现场断网失效，或维护者修错生成文件导致下次构建覆盖。 | 模拟数据继续由 `createSimulation()` 和统一 `elapsed/timeFor()` 驱动；模型接收时间、运行状态，不自行推进计数。主循环限制异常帧跨度；低帧率不能靠更改周期或良率来掩盖。背景与接触纹理由 Canvas 本地生成。构建保持本地 Three.js alias、IIFE、内嵌字体/布局/附件/许可证，生成根目录和 standalone 两份 HTML；维护源码后统一重建。 |

## 必须保持的边界

- **对象归属独立于美术表现。** 源对象 ID 决定设备与区域，`partId` 决定可拆总成。新增凹槽、螺钉和指示灯是这些总成的视觉子对象，不能因为模型更细就增加现场设备数量或宣称真实内部结构。
- **模拟逻辑独立于镜头和布景。** 镜头切换、侧栏显隐、标签减量不重置 `sim.elapsed`；进入检查/拆解按已有交互暂停，启动时等待复位完成。演示的阶段时长、统计周期、示例不良率与温度函数不在视觉优化中改写。`equipmentCycles` 与统计周期若未来确需调整，应作为单独的模拟改动审查。
- **资源按拥有者回收。** 模块共享的 geometry/material 长期复用；模型创建的 tube、克隆材质和实例缓冲随模型退出释放；车间布景及车间实例网格随车间替换释放。背景纹理、接触纹理、PMREM 环境图、控件监听器和 ResizeObserver 属于整个 workshop 生命周期；若未来支持销毁/重新挂载，需统一释放，不能在每次切车间时误删。
- **交付方式独立于开发方式。** 开发源码可以分模块，交付 HTML 仍不能新增运行期 CDN、fetch 资源、远程字体或模块加载。程序化纹理无外部素材请求；若将来换入照片/HDR/glTF，先落实授权、内嵌或离线资源方案再修改交付承诺。

## 本轮已记录的回归结果

主任务提供的浏览器回归结果为 PASS：暂停时模拟时间固定；拆合后自动恢复运行；专注展示进入设备详情后恢复面板；手机布局拆解可操作。连续 4 轮切换车间后，`geometries = 32`、`textures = 4` 保持稳定；记录的总览 `draw calls = 478`。该轮使用软件渲染，以上绘制批次和资源计数不代表真实展厅电脑或手机的 fps，也不能据此承诺实际 GPU 帧率或发热表现。

源码已核对工艺近景选择同步、`currentCamera`、手动接管、focus resize、Escape 退出专注、车间实例缓冲释放及框架四批次实例化。这些修复已实现；除上述明确 PASS 的路径外，完整联动仍按以下清单复验，不再将旧状态缺口列为现存问题。

## 最终验收应保留的证据

下列为维护和发布时的复验清单；本轮已执行结果见上一节。记录与最后一次构建对应的版本、设备、窗口尺寸和浏览器；最终美术评审后再统一更新 `DESIGN.md`。

| 检查点 | 应看到的结果 / 需要记录的证据 |
| --- | --- |
| 选择与总成归属 | 每类设备至少一个主要表面和一个重复细节可定位到正确总成；选中、单拆、显隐和说明对应同一个 ID。 |
| 返回与接管 | 反向/俯视/近景、手动拖动、巡览、进入结构、返回车间、专注展示开关连续操作后，没有相机自行抢回、选择错位或面板不可恢复。固定视点按钮反映真实模式。 |
| 标签与引线 | 桌面与窄屏的装配/半拆解/全拆解状态均可辨认；旋转、筛选、隐藏部件后无遗留标签，标签端点跟随正确对象。 |
| 性能与资源 | 使用 `?review=1` 的只读诊断记录 draw calls、triangles、geometries、textures，并记录帧时间。连续切车间、进入/退出结构、切换所选部件后，资源应稳定到可解释的范围；首次着色器编译或合理缓存不能直接判为泄漏。手机以实际操作帧率和发热表现判断预算。 |
| 模拟连续性 | 暂停时动作和计数冻结，继续时姿态连续；拆解后启动先复位；相同模拟时间的指标与视觉切换前一致，所有指标仍明确标注模拟。 |
| 单文件交付 | 根目录与 standalone 构建产物一致；断网以 `file://` 打开仍有字体、程序化纹理、布局和完整交互；附件可导出；原光引擎独立展项入口仍解释完整项目的进入方式。 |
| 事实边界 | 布景不加入原图计数与碰撞；无未经来源支持的尺寸、品牌型号或生产参数；“布局依据/通用结构/模拟”说明在各主要使用路径可见。 |

## 维护清单

- 先修改 `src/`、模板与样式，再执行现有单文件构建；不要手改生成 HTML 作为唯一修复。
- 新部件先确定所属总成和动画父级，再决定共享 Mesh 或 InstancedMesh；避免跨多个可拆部件合成一批实例。
- 改变状态灯、选中高亮或运行反馈前，确认材质是专属克隆；不得直接改共享 `MATERIALS` 的实时状态。
- 每项新建 geometry/material/texture/instance buffer 要写清拥有者和释放时机；资源检查覆盖模型、车间和整个 workshop 三层。
- 灯光、DPR、透明材质或阴影参数变更后，使用同一目标机器、同一镜头、同一运行阶段作前后比较；不要以截图更亮替代性能结论。
- 改视点/专注展示时，同时检查选中 ID、侧栏、激活按钮、resize、手动接管和返回路径；相机状态不应偷改模拟状态。
- 改标签时保留清单/搜索/二维图作为发现入口，并核对部件显隐、长名称与触屏点选。
- 新布景只在展示模块维护；原始布局、区域和设备数量只从源数据更新；新增外部素材要同步授权记录与离线打包。
- 最终美术评审后统一更新设计说明、构建产物与验收记录；记录本次实际采用的效果，不提前把候选效果写成已交付能力。

## 回退层级

按影响最小的层级逐级回退，每级只在解决对应问题后停止；回退也要重建两份单文件产物。

1. **GPU 画质回退：** 先将阴影图降到 1024、DPR 降到 1，关闭非关键小件的阴影。保留材质类别、选择反馈、设备动作和源布局；若未来加入 AO/后处理，优先关闭它们。
2. **展示装饰回退：** 简化/去掉框架、灯带、接触暗部和高密度细节；保留设备主要轮廓与可拆总成。移除装饰要走拥有者的资源释放，不改布局事实。
3. **交互增强回退：** 若固定视点或专注展示影响返回/接管，先撤掉对应入口，恢复稳定的旋转、缩放、总览与俯视；标签引线有歧义时退回既有标签，并保留清单/部件列表。选择和模拟继续工作。
4. **模型细化回退：** 保持既有 `parts` ID、名称、拆解方向及动画接口，退回上一版低细节几何；不要用回退模型顺带替换或重置模拟统计。
5. **整包回退：** 若无法隔离交付故障，使用已保存且有对应验收证据的完整版本（源码、vendor、数据和两份 HTML 一起）。不混用新模板、旧 bundle 和不匹配的许可证；原始源布局及附件仍保留。
